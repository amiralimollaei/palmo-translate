# Documentation

Write project documentation for readers who have no prior knowledge of this project or its development history.

- Explain what the project does, prerequisites, and relevant concepts before relying on project-specific terminology.
- Describe the current behavior and give self-contained instructions and examples.
- Do not write README files or guides as development recaps. Avoid phrases such as "unchanged," "still supported," "as before," or references to removed or former implementations that require historical context.
- Put version-specific changes and migration instructions in explicitly labeled release notes or migration guides when requested, not in general onboarding documentation.
